# ordessa-harness-qoder

Independent brand package (032): the qoder native-channel facts and deploy
knowledge moved out of the retired root `pacthold.harness_kit` super-package. No
aggregate registration; the product selects brands explicitly.

## Current SDK convergence

A factory is published through `ordessa.harness_providers`; this is discoverable
metadata, not a claim of executable availability. Exact Profile pin and empty
configuration validate, while any declaration compilation is explicitly
unavailable. The existing first-hand key registry is retained unchanged. No
native command/protocol/login source is established in this leaf, so prepare
refuses `NATIVE_LAUNCH_UNAVAILABLE`, session refuses native bootstrap. No guessed
CLI, direct process path, old Unit registry or ACP fallback was added. Original
registry assertions remain the acceptance baseline; no real Qoder/model called.

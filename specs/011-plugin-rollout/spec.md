# Spec：并行实施、公开接缝与可审核交付

## 用户目标
在隔离工作树中完成已设计的 Harness、Profile、Chat、模型、内容资源、MCP 和安全插件，让主代理负责拆分、子代理派发、审阅和阶段提交。小型类型/构建/夹具问题由执行者在范围内修复；公共接口及生产链有明确所有者。

## 需求
- R01：九树从同一文档快照开始；每树独立 venv/node_modules/临时数据根，不重装根树或其他树的 editable 包。
- R02：C0 先验收已有平台 A/C 与侧栏提交，核对 stop unknown 租约问题；B 原会话继续收尾，新树不干扰、不接管。等 B 发布最终提交后固定 SHA 集成，并核实历史迁移提供者缺席等登记问题是否已解决；只有收尾交接后的剩余集成缺陷归 C0 修复。通过后才发布 foundation。
- R03：C0/Z1/Z2/Q5 提前发布真实可导入契约和最小 proof，消费者按固定提交消费，不复制 Token、不发明临时 ServiceLocator。
- R04：一个文件面有一个实施所有者；每个实施子代理只写一个包，跨包变更串行另派。各主代理只审阅、运行验证、维护文档和 git，不亲自编辑生产/测试代码。
- R05：消费者遇上游未发布先做独立任务，记录精确接缝需求，按检查点协议继续；只有真实新产品裁定、敏感数据/模型授权或基础能力无法兑现才暂停对应任务。
- R06：所有原包任务须可追踪到实现、正反例和日志。数量不能替代失败 ID/原因；收集失败、缺测试命令、模拟生产接口均不能报完成。
- R07：插件在缺 Profile/Chat 等可选 glue 时按各包语义工作；MCP 受管调用、强制安全策略缺执行前权威时拒绝相关操作。
- R08：不改根分支、不动旧树脏项、不操作既有服务、不读私人凭据；真实模型、真实外部服务副作用、main 合并、push 另需明确授权。
- R09：C0 统一集成 products、根 workspace/生成 lock、tooling 与 compat 公共注册/组合；业务线交接线清单，不能共同删除同一公共所有者。
- R10：完成后交付本线 clean commit + FINAL/REVIEW_READY 报告和检查点。未通过项列 PARTIAL，不以“达到一个阶段”提前终止整项工作。

## 本轮授权覆盖
旧 AGENTS/baseline 仍把 Profile/Provider 视为外部仓、限定最早迁移提交起点，属于旧基线描述。本轮用户明确批准在 monorepo 内实施这些业务域，且授权工作树从本次设计快照派生；不因此改变历史数据 ID 或批准主线合并。010 宪章的边界/证据原则继续适用，旧“仅平台收敛”范围由本目录扩展为已列领域包。

## 完成条件
每线：原实施包条目全覆盖，公开接口生产接线按证据等级通过，依赖方向及所迁测试保真，真实 UI/受控协议验证齐备。全局：C0 在集成树复跑受影响套件和已登记账本；只有涉及已明确支持的格全部通过才报完整交付，未知或不可实现格如实保留。

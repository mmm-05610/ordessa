## 已确认的规则

1. `frontend/`、`backend/`、`plugins/harness/`、`plugins/assets/` 是目录组，不是可安装的总包或另一个宿主。
2. Agent、Profile 的持久权威和管理规则只属于 Pacthold；UI/CLI/决策模块是消费者。
3. 品牌插件负责真实实例、原生配置和通道。公共内核不理解 Codex/Pi/Claude 的配置字段、协议及内部工作流。
4. Profile JSON 是配置输入，不承载启动、暂停、终止等生命周期命令。
5. Server 提供协议入口与插件托管，产品负责绑定；两者不维护第二套 Agent/Profile 状态。
6. 删除旧源码时同时处理注册、依赖、锁文件、脚本、测试与文档。数据兼容通过显式离线迁移解决，不保留运行时旧实现。
7. 尚未迁入的新能力显式不可用；不能添加委托回旧插件的代理实现。

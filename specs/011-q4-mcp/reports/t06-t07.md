`backend/secret.py`
- 模块内登记码（secret.py:53-54）：`PLAN_STALE`、`MCP_PLAN_BINDING_INVALID`；`SECRET_UNRESOLVED` 沿用 `errors.py`
- `CredentialPort` Protocol（:61）：`has(credential_id) -> bool`、`read(credential_id) -> (plaintext, revision)`
- `HostCredentialPort` + `host_credential_port`（:76/:133）：**注入式**薄适配器包 apps/server `CredentialRecords.exists/get(secret_locator)` + pacthold `SecretStore.read(locator)` 两层（不 import 宿主模块，守插件边界）；`secret_store=None`（非 NT）→ `has` 恒 False、`read` 抛 `SECRET_UNRESOLVED`（fail-closed，G7 约定）；宿主无 credential revision 计数器（已登记局限）→ 以存储字节 `sha256:` 内容摘要充当 revision 身份：轮换改字节即改摘要即被 stale 抓住，撤销删记录即 `has` 失败；底层异常仅引用类型名入消息（locator 路径/明文不外泄）
- `CredentialBinding`（:139）：对齐 `resolve.py` 快照 `credential_ref_revisions` 条目四字段（definition_id/revision/slot/credential_id）+ 计划期冻结的 `bound_revision` + `kind(env|header)`；未绑 revision 直接 `MCP_PLAN_BINDING_INVALID`
- `LaunchPlan`（:172）：principal + bindings + session_ref + `expires_at`；重复槽位拒绝
- `SlotProof`（:194）：每槽证明，仅 slot/credentialId/revision，无明文
- `ResolvedSecrets`（:213）：瞬时 env/header 注入映射（`.env/.headers`）；`__repr__/__str__` 只出槽名+credentialId+revision；`references()`（:249）给持久层/API 的 ref-only 视图；`__getstate__/__deepcopy__` 抛错（不可序列化=明文不出内存域）
- `snapshot_credential_bindings`（:274）：从快照 `credential_ref_revisions` 冻结 plan 绑定，任一槽无观测 revision → `SECRET_UNRESOLVED`（plan 永不携带未绑秘密槽）
- `resolve_for_launch`（:313）：过期先拒（不触 store）→ 每槽 `has`（撤销→unresolved）→ `read`+revision 比对（轮换→`PLAN_STALE`）→ **整批语义**：任一槽失配则全批不放行（异常先于任何返回，部分注入不存在）；消息只点名槽与 credential id
- `redact`（:400）：dict（含键）/list/tuple/set/str/bytes 深度扫描，任何已解析值替为 `***`，形状保留；接受 `ResolvedSecrets`、单值或可迭代值

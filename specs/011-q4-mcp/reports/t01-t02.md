## 布局选择及理由

采用任务书的倾向方案：**扁平 `backend/` + 包根 `conftest.py` sys.path 注入**（`plugins/assets/mcp/conftest.py:1-13`），不建 `src/ordessa_mcp` 布局。理由：

- 匹配 `docs/design/mcp/plan.md` 的字面路径 `plugins/assets/mcp/backend/…`，主代理对照设计文档可直接定位；
- `python -m pytest plugins/assets/mcp` 从仓库根零安装可跑（conftest 把包根插入 `sys.path`，测试 `from backend.definition import …`）；
- `pyproject.toml` 仍保留合法 setuptools 打包面（`packages.find where=["."] include=["backend*"]`），T09 装配需要 pip 安装时不改造（name `ordessa-mcp`, version 0.1.0, requires-python>=3.9，与 server-compat 同风格）。
- 已知代价：`backend` 是顶层通用名，仅在本工作树 pytest 路径下成立；本包不做 `pip install -e`，不与 venv 中其它包竞争命名空间。若 T09 要安装发布，应届时改 `src/` 布局（已在本报告登记为偏差候选）。

存储决策按 `specs/011-q4-mcp/t00-interface-bindings.md`（🟡 行）：**域自持文件存储**，不请求改 pacthold 中心 schema。定义修订文件保持 legacy 布局 `<root>/mcp/<definition_id>/<revision>/server.json`（0o644、staging+`os.rename` 原子写、不覆写已有修订）；元数据在 `<root>/mcp/index.json`；分配表在 `<root>/assignments/assignments.json`。并发策略（写入两模块 docstring）：每次读-改-写持 `fcntl.flock` 排他锁（`<root>/mcp/.lock` / `<root>/assignments/.lock`），提交用 `os.replace`；修订文件本身不可变，rename 即定稿。

## 与设计文档/任务书的偏差及依据

- **D1 快照字段扩展**：`McpEffectiveSnapshot` 在 data-model 列举字段外增 `needs_revalidation: tuple`，并把 `laneByDefinition` 的值定为 `{lane, enforcement}`。依据：data-model 正文本身要求「catalogDigest 变化→旧快照标 needs-revalidation」「无法限缩→降格进快照」，字段没有别的落点。
- **D2 `allObserved` 在分配时冻结当次观测名集**（连同 catalogDigest）。依据：T03 前目录无持久留存，若不冻结名集，「仅绑定当前 digest + 新工具不自动加入」无法在 resolve 时执行；冻结方向是收紧不是扩权。
- **D3 enable 必须带工具选择**（缺省拒绝 `MCP_ASSIGNMENT_INVALID`）。依据：FR-04「工具子集与服务器启用一起冻结于会话快照」，比 data-model 字段列表（toolSelection 可空）更严。
- **D4 v2 写路径接受 legacy `{"credentialRef": id}` 形状并归一化为 `secretRef`**。任务书只要求「读取/校验兼容」，此处放宽到写路径以保证 FR-12「不修改磁盘标识」下旧客户端仍可重存同一内容；digest 用归一后形状，故同一旧内容的 v2 重存会得**新**摘要——旧 revision 文件本身永不重算（`adopt_legacy_revision` 通道保持旧摘要），无「无声重算」。如评审认为写路径应硬拒 legacy 形状，改一行 `_typed_references` 分支即可，测试 `test_oversized_nul_and_badly_shaped_values_refuse` 需同步反转一例。
- **D5 跨 scope 读一律 `MCP_ASSET_MISSING`（不泄露存在性），写/篡改冒领才给 `MCP_SERVER_SCOPE_CONFLICT`**；`install_legacy` 不校验 asset_id（legacy 原行为即不校验，字节保真优先），新 API 全部前置 `_validate_definition_id`。
- **D6 serverScope 逻辑隔离**：同一 store root 内以记录字段+入口校验隔离，未做物理分目录（布局 `<root>/mcp/<id>/<rev>/server.json` 与 legacy 完全同形是硬约束，scope 前缀目录会破坏它）。隔离强度由测试 `test_cross_scope_read_is_refused_without_leaking_and_write_conflicts`、`test_cross_server_scope_assignment_is_refused` 钉住。

# Production Agent facade raw submission fence

Root ordinary implementation decision under 013: the current Chat production composer already uses real DurableSubmissionClient and IndexedDB, with no storage/raw fallback. The historical AgentSessions facade still exposes methods that bypass it. These methods must not become an implicit alternate reliable route after unknown, client replacement or generation change.

Implementation-only createAgentSessions adds an options policy reliable-only versus legacy-raw-fixture. The loadable product entry always selects reliable-only; direct historical isolated factories retain their fixture behavior. Public AgentSessions contract signatures stay unchanged. Production send returns typed refused/CAPABILITY_UNSUPPORTED before client lookup/calls; newSession and prepareSubmission reject with typed code CAPABILITY_UNSUPPORTED before native creation or owner preparation. Reads, draft selection, project navigation and exact readonly owner lookup remain unchanged. Existing Chat reliable adapter remains the only ordinary production submit path. No new journal/owner/config authority and no Harness internals.

This closes the legacy facade submission bypass only. It does not pretend to complete ACP alias/run/interaction durable migration or prove unverified second-native-connection ownership. Those absent native authority/owner/generation/continuity producers remain explicit gaps; reliable failure must never fabricate admissionEvidence or fall back. Tests must use the actual product entry, reproduce existing raw calls before guard, retain old fixture assertions, and verify all guarded operations invoke zero native effects. Current4ad artifact predates this forthcoming guard and must not be credited with it.

== STEP-1 DETERMINATION: the seam is HALF drivable from a plugin — (a) for the
tool-execution fence, (b) for the submission fence ==

Decision basis (read of apps/server/src/ordessa_server/acp_admission.py in full,
then measured against the real classes with an in-process fake channel, before
any test or module was written):

(a) `AcpPermitAuthority.authorize_permission(connection, request, decision) -> bool`
    (acp_admission.py:39-42,204) is answered with a plain bool and the fence
    requires `is True`. No host type is involved, so a plugin CAN be that
    verifier with only `server_plugin_api` imported. -> implemented in src.
(b) `authorize_submission` CANNOT be satisfied from a plugin:
    * acp_admission.py:134 rejects the permit unless
      `isinstance(bound, BoundAdmission)`, and `BoundAdmission` is declared in
      the host module itself (acp_admission.py:27-36);
    * it is NOT published by the public contract:
      `packages/server-plugin-api/src/server_plugin_api/acp_admission.py` declares
      only AcpChannelBinding / AcpAttachmentReference / AcpSubmissionRequest /
      AcpPermissionDecision / AcpAdmissionResult / AcpAdmissionPort, and
      `__init__.py:26-28,116-117` re-exports just ACP_ADMISSION_PORT(+VERSION)
      and those DTOs. Measured: hasattr(server_plugin_api,"BoundAdmission")=False,
      "AcpPermitAuthority"=False, "AcpAdmissionRefused"=False.
    * importing it is forbidden in this package, not merely discouraged:
      tests/test_backend_dependency_direction.py ALLOWED_ROOTS =
      {__future__, ordessa_permissions_api, server_plugin_api} and its
      FORBIDDEN_ROOTS scan rejects even the literal text in src/.
    * the permit's `input_digest` must equal the host's private canonicalisation
      (`_digest`/`prompt_input`, acp_admission.py:63-90, computed at :120); no
      public recipe exists.
    * only the host's own `AcpAdmissionRefused` (acp_admission.py:21) is mapped
      to a typed refusal by the public port adapter (:383-384); a plugin-raised
      exception collapses to `unknown` (:385-387), losing the stable code FR-09
      requires. Measured below (O5/O6).
    -> src refuses that half and takes the permit record as an injected binder.

   the prompt frame is admitted (the recorder shows exactly one line).
O3 AcpAdmissionGate() with no authority (= bootstrap/runtime.py:607)
   -> authorize_submission and authorize_permission both raise
      CAPABILITY_UNSUPPORTED; the real AcpAdmissionPortAdapter answers
      refused/CAPABILITY_UNSUPPORTED and `ready` is False (:311-319 hardcodes
      it); the prompt frame is refused ("lacks matching one-use admission");
      zero recorded effects. The absence is fail-closed, never permissive.
O4 authority raising AcpAdmissionRefused("POLICY_DENY", ...) through the real
   adapter -> AcpAdmissionResult(kind="refused", code="POLICY_DENY") — the code
   survives ONLY because the type is the host's.
O5 authority raising a plugin-owned ValueError through the real adapter
   -> AcpAdmissionResult(kind="unknown", code=None, reason="ACP admission
      outcome needs reconciliation").
O6 relay shape (transport/http/app.py:297-306): admit_client_frame runs BEFORE
   transport.send_line; any refusal (typed or generic) means no line reaches
   the Agent, which makes `transport.sent` a direct effect measurement.

# 能力边界

版本：B1 + 用户裁决记录（供 V1 攻击）。V1 原始模型不改写历史；后续 V2 纳入裁决。

## 可以先给非专家解释的范围

把环境看成一个能装入不同参与者的工作场所：它知道谁在场、什么入口可用、谁可以使用、哪些东西还在运行，以及移走谁会影响谁。它不代替 Agent 思考，也不把 Agent 的所有操作重新写成自己的菜单。

原生会话像参与者自己的工作室。环境可以给它开门、记录使用和失联事实，不能把工作室内部的工具调用当作自己执行，也不能因为关掉一个观察窗口就认为工作已完成。

## 确定的方向（README §2）

1. 完整参与者优先；原生机制属于参与者，内核不理解 ACP/Codex 等品牌。
2. 装入与移除是生命周期，而非只注册几个调用函数。
3. 一个后端环境权威；Server 是入口/transport 装配者，不再独立管理另一套插件执行中心。
4. 经环境暴露的调用有统一活动语义；持久化、使用许可与核对是正交保障，普通查询不强制变成持久任务。
5. 可选增强不能占据唯一原生入口；历史/unknown 保留，不假报自动恢复或完成。
6. 顶层 backend/frontend 仅包组，包数由职责决定。本轮不改生产和数据。

## 候选内核能力（技术提案，不是已冻结 API）

| 边界 | 内核承担 | 留给插件/外部参与者 | 缺席行为 |
| --- | --- | --- | --- |
| 来源/安装单元 | 登记来源摘要、版本、兼容需求、安装事实 | 下载、包管理、供应链审核、品牌启动脚本 | 未安装不得激活；不自行联网安装 |
| 激活/实例 | 声明依赖、事务发布、实例身份与代际、准入/退役 | 实例工厂、具体健康/进程证据 | 必需依赖缺失，整组拒绝半激活 |
| 交互表面 | 方法/流/双向入口载体，限额、授权端口、相关性 | 协议编解码、原生 UI、命令语义与审批 | 未承载 UI/命令明确 unavailable，不能假报自动可用 |
| 活动 | 入参快照、请求/结果/取消事实、统一证据投影 | 工作流/推理/工具内部事务 | 无 terminal evidence 维持 unknown/运行中 |
| 对象/使用 | locator 与 owner/usage/destroy 关系、引用代际校验 | 真实对象存储、销毁或核对执行 | owner 未知/实现缺失不可控制；只读历史可用 |
| 保障选择 | 内存/持久事实，去重范围，核对声明 | 证据来源、外部幂等/恢复能力 | 缺少保障明确降级或拒绝要求该保障的请求 |
| 组合/并发 | 父子关联、依赖图/锁与部分结果 | Agent 协作业务与补偿决策 | 循环拒绝；主因/清理结果分别可见 |
| 观察 | 有界 envelope、订阅与 gap、敏感等级 | payload 解码、业务 renderer | 未知只展示/保存可允许内容，不当审批/终态 |
| transport | 同一个中性运行入口 | HTTP/WS/CLI 鉴权/序列化、路由贡献 | 无网络插件时本地入口仍可用 |

## 统一权威不是吞并原生状态

- 内核裁定环境准入、句柄可用性、调用的可知事实、依赖和管理归属。
- 插件/原生裁定内部会话、命令、工具审批和原生对象的真实状态；内核只接受带身份/版本的证据，不能凭失联发明终态。
- 领域 Work/Profile/Skills 与 transport 索引可有各自持久化和投影；它们不能同时成为同一执行事实的独立主写者。
- 内核统一暴露的 ingress 活动记录，不要求为每一条原生内部帧/工具调用创建 Execution。参与者内部副作用是声明的未接管范围。

## 用户裁决与实施前待决

- D1（2026-10-03 已选）：「采用入口授权，原生负责内部审批」。未知原生命令只要已有承载入口可达，不需内核认识命令；每次使用仍校入口/实例/使用者权限，不能放宽原生审批。
- D2（2026-10-03 已选）：「可以，正常移除先等已有工作结束」。默认先关闭新准入，保留已有工作所需实现与核对入口，完成/确认停止后移除。立即移除另需明确要求；若发生，不能声称已停止。
- D3（实施前待决，沿用B1编号）：未来持久数据写迁移方式/标识兼容需用户确认和钉死实施基线；本轮仅提供无写入方案，不迁移数据。
- D4（本轮新增，待答）：已有工作的必要收尾链是否允许继续，包括停止时的新原生确认、晚到对象收尾、既存依赖查询；建议允许但不得启动新业务。
- D5（本轮新增，待答）：owned原生实例发现partial/opaque时，正常移除是否必须有充分范围停止证据；建议证明不足时保持移除待完成，不仅改报告措辞。
- D6（本轮新增，待答）：effectful未知输入采用通用protected fingerprint；能力缺失发前明确拒绝的安全前提；建议采用，保命令透传而非命令白名单。

编号勘误：第二轮后最初复查消息将上述三项临时叫D3/D4/D5，与B1的数据迁移D3冲突。2026-10-03独立复查指出后，当前模型/计划/账本统一为D4/D5/D6，原D3含义不改。用户问题本身未用这些编号，因此不改变用户答复含义。

## 安全限制与非目标

有鉴权端口不等于提供 sandbox。当前 Python 进程内插件是受信任代码；句柄校验防止环境 API 越权，不能阻止恶意插件直接读 OS/内存。安装/启用不默认授予系统权限；若要容纳不可信执行代码，应先选已有进程隔离/沙箱宿主和授权方案，不能包装成同进程安全。

不接管内部 inference/tool scheduling/compaction/workflow/记忆；不保证外部 exactly-once、分布式共识/集群调度；不实现通用 workflow DSL、不做网络包管理器、不新建品牌特殊 API、不要求 Profile、不造平行宿主或 sandbox。
不要求两个前后端实体完全对称。前端变化只列契约影响。

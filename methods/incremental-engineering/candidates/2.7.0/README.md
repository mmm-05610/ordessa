# Incremental Engineering 2.7.0 candidate

Status: unpublished, schema-2 declaration only, not executable. `method.json` captures the `ordessa.methods/actions-v1` method definition. Its three method-owned actions describe explicit change review/registration, package preparation, and implementation plus independent review. None is connected to an application runner or old `WorkflowSpec` interpreter. Calling `compile_method` on this schema returns `METHOD_EXECUTION_UNSUPPORTED`; no V1 fallback exists.

The actions are finite ordered `invoke`, `record`, and `emit` declarations. Change review invokes the method-owned JEV review operation, records its result, and registers only behind step-local complete, passed, exact-input, same-scope, method-pin, and baseline-available gates. It does not insert an extra human-review step. Package preparation declares same-scope, exact-input, method-pin, review-complete, review-passed, and baseline-available admission. The implementation action binds a caller-supplied execution profile and a separate caller-supplied reviewer profile to distinct steps; `reviewer_independent` is a declaration requiring a future trusted application check, not proof that profiles differ or that a review actually occurred. The ordered disposition operation is a finite declaration; review completion, cancellation, unknown results, and a caller-approved one-operation rework are not executed by this package.

Baseline and candidate are exact external `SourceRef`/`SourceLocator`/`VersionCapture` identities, not `ArtifactRevisionRef`, repository snapshots, or commits. The sample scope is realm `example-realm` and project `alpha`; the source document id is `alpha:design/DID.md`, with upstream versions `baseline-v1` and `candidate-v2` and the exact SHA-256 captures in the shared sample. Digests identify captured bytes and do not establish access to or recovery of baseline content.

Criteria and prompts are versioned text resources and are not interpreted as machine predicates. The three schemas for review results, package results, and implementation reports are explicitly candidate external-contract proposals. In particular, the review proposal is not a current Engineering `ReviewRecord`, which cannot express an external-only review target. Existing Spec Kit templates are captured under the candidate's resource index so their exact bytes are versioned with this declaration.

Package preparation and implementation routes require explicit caller-supplied execution profile refs. JEV review is not routed through an execution profile; its production method/application binding is not connected here. No production execution profile is bound in this candidate, no automatic profile creation, no discussion capture, no automatic DID generation, no draft-save trigger, and no project-wide phase enforcement. A future application must bind trusted profile and JEV review ports, material access, domain records and operation-local admission before any declared action can run. Until those owners migrate, this candidate is not a usable workflow.

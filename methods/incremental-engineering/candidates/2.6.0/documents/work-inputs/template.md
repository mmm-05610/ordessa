# Incremental Engineering work inputs

Create a new immutable artifact revision for this exact Work run and selected Proposal. Then explicitly pin that exact revision with the original `engineering.work.bind_inputs` command using its expected Work row digest and next-step ordinal. `append_revision` does not move an accepted artifact head. Add data only for the current wait node, using its declared fields in the 2.6.0 workflow. Future event nodes may be omitted until needed.

`run_id` and `proposal_ref` bind the document to the selected original Work. `events` keys are exact workflow wait-node IDs; each event object accepts only the fields declared for that node. The Engineering Work source checks the current node’s expected event fields and resolves references, plans, grants, and results through the original same-library owners. Rebinding a different input revision is a Work-row CAS operation; no implicit latest/head lookup is used.

For review-response waits, store the UTF-8 response in the original same-authority BlobStore and provide the exact `BlobRef` as `raw_response_ref`; do not inline raw response text. At `await_implementation_permission`, `dispatch_input` is input data only; canonical dispatch rechecks the full actual action tuple and current Grant through its original owner. That wait does not mean permission was granted. Do not add readiness, acceptance, permission, verification, or equivalent truth flags. A submitted reference or result-shaped value is not proof that its owner accepted it. Missing, stale, mismatched, unknown, or revoked inputs leave Work waiting or refused.

# 有依据地提出 DID 增改删

使用 document.did_change.schema/template 与 document.session_summary.schema/template。固定基线/目标、决定上下文、全部有效依据与 standard profile。ECP/NOR 逐条 add/modify/delete/retain；每条说明为何依据在适用范围内支持完整语义，保存已知反证。观察、参考、假设不能独自批准新行为。事实先只读查证；重要未知留阻塞和受影响切片。只起草，不改正式 DID。

资源身份以当前 work.method_ref 固定的编译资源为准，不读 latest。所有副作用使用已注册 operation、稳定 request_id 与精确refs；能力缺失明确阻塞，Skill不自造后台状态。

# 夜间接入执行规则

本目录是029原实施队列的追加批次，唯一执行者仍是原会话；不启动第二执行者抢同一树。现有docs/implementation/agent-tools下的规则和R-0001至R-0006保持权威，本包按R-0001边界和用户本轮十家扩展请求执行。技术范围见[030](../../../../specs/030-native-harness-expansion/README.md)。

## 模式与顺序

采用一执行者、一树、有界队列；完成后交接，不设置定时器、不建立后台自唤醒程序。N001前置核查 → N002–N011十家 → N012整合安装。某家BLOCKED继续其他无依赖项。必须先有第一家真实纵向接缝，再批量实现同类家族；不是十个空适配器。

主执行者独占共享registry/schema/配置公开合同、CLI主入口、测试总运行、status和Git。家族纯研究与冻结合同后的独立家族实现可按工单parallel_units委派；每个工作单元限定family目录及测试，不写共享文件。现有章程允许子代理，本夜最多3个活跃子代理、深度1；不新增用户会话/工作树。子代理不写契约/账本、不做Git操作、不运行共享editable安装或全集测试；主执行者亲自复跑。

## 本夜权限

- 可查公开资料、下载源码研究、运行现有专属环境的受控测试、自建临时loopback测试服务并清理。
- 可按仓库既定工具链安装实施所需测试依赖到专属venv/本地工作区；真实第三方Harness的新安装/更新仅在既有明确授权内，否则登记待授权。不能npm -g/uv tool install/sudo、执行curl|bash安装器或改/opt。
- 真实已安装Harness也不是自动允许读用户登录home。仅隔离HOME/XDG/家族home、干净env、无用户Token、禁外部模型网络、确认无启动hook/遥测/更新effect后才做L2。命令--version也先查启动副作用。
- 不进行真实模型调用，预算0；SDK/免费额度/已有会员同样不自动授权。没有用户批准scope+cost即L4未测。
- 不改用户账号、认证、全局Skill/配置、运行DB；不重启用户服务；不push、不主树合并。
- 临时网络测试仅loopback随机端口＋临时认证；禁0.0.0.0、公网/远端部署。日志脱敏，Token不进命令参数/文档/Git。

## 连续执行与交接

每单阶段提交前重读原规则与本包，纳入新要求留回执；有缺口汇总status Questions并继续独立工作。每家时间集中在实际进度，纯环境/下载障碍连续两次无新证据就换家，不反复烧时间。不能越权“因为用户睡了”自动审批。

检查点名checkpoint/agent-tools-native-030-Nxxx，不覆盖现有tag。只提交本人明确路径并核暂存，不卷入用户改动。完成可做反例/恢复/分发/文档复查；全部安全队列完成后给终报告，不无限探索、不扩大功能。保留失败、未测与清理证据。原主status只由原执行者更新指针，本夜细账在status.md，避免多份互相独立权威。

# UX：管理、选择、运行状态分开

## Settings 的 MCP 区

列表每行展示定义名、transport、批准修订、来源、引用状态、上次**探测**结果；“探测成功”文字不得变成“会话已连接”。编辑 stdio command/args/cwd 与可读常量、SecretRef 引用；远端 URL/headers/授权引用。秘密输入委托统一凭据提供者，页面不回显明文。保存候选版本后另有“批准并用于选择”动作；旧分配默认仍引用旧版。可做有限探测并展示其**无凭据/有凭据**范围。缺 Credential 服务时 secretRef 字段只读且不能应用，不造内部 vault。

## Profile 编辑

由 MCP 自己向 Profile 注册配置面，展示可用定义、批准版本、启用/禁用/继承及本版本工具子集；不把 MCP 记录复制进 Profile。原生发现但非受管的 server 分组单独显示，不能让用户以为点击禁用会关闭它。提供者未安装则配置面直接消失，已存数据保留；不显示“坏掉的空卡”。Profile 在某 Harness 下无法受控装载某 server/lane，条目标 unsupported/unknown，不提供虚假确认按钮。

## Chat 输入区与状态

在输入区按需打开 MCP 状态/选择器，显示本会话已确认的定义、工具数量及明确证据等级；Pending 和 Unknown 不是 Connected。输出期间的变更仅更新下轮待用选择，**不弹复杂状态台**、不打断当前输出；下一次用户提交由同一提交闸门执行配置/连接计划。失败时保留草稿并给“查看原因/受控重试”，不自动重新发送用户文本。真实工具调用若需审批，用既有审批 UI，不由 MCP 画第二套审批弹窗。

无人值守时界面缺席：已预授权且满足完整约束的工具可执行并审计；未知/外部副作用工具留在待审批或拒绝，不因无人点击而默认允许。审计可在会话活动/工具卡中引用定义版本、工具名、决策 ID、结果；不泄露原始参数中的密钥。

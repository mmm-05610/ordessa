# Feature specification

## 用户故事与独立验证

### US1 / P1：配置能力可以独立接入

Skills 开发者添加某品牌格式适配，不修改 Harness 主流程或核心包；没有 Profile 时仍可管理 Skill。Given 一个受控品牌与配置提供者，When 注册/卸载，Then 对应能力出现/消失，历史配置保留，未注册项不能下发。

### US2 / P1：同一会话安全切换配置

用户输出期间选择同 Harness 的另一个 Profile，或单改 provider/model。Given A 输出中且 B 并发运行，When 用户选择，Then A 不被打断、B 不变；下一次提交才应用新配置，确认后只发一次原消息。独立测试必须通过生产提交入口，不能只测 apply 函数。

### US3 / P1：需要重启也不丢对话

Given 目标版本只支持重启后恢复，When 配置变化，Then 保存可恢复身份、关闭已证明属于本实例的资源、建立新 generation、恢复同一会话；无法证明恢复时停止发送并报明确问题，不能新建空白会话代替。终态 execution 不能复活。

### US4 / P1：新增品牌不要求改全部业务

Given 第三方受控 runtime adapter，When 经注册点加载，Then 可启动/连接/关闭；只装它支持的业务配置适配即可。没有模型切换或 Skill 能力不妨碍诚实提供其他已验证能力。

### US5 / P1：失败不变成假成功或串配置

Given 崩溃、超时、插件卸载、文件冲突、恢复失败，When 重试/查询，Then 返回确定拒绝或未知结果，不自动重发、不把半应用记为 Profile 已生效；另一会话与用户全局配置字节不变。

## 功能需求

| ID | 必须实现 |
| --- | --- |
| FR01 | 两个领域注册点：runtime adapters、configuration adapters；所有权由宿主注入，原子注册，版本和重复拒绝 |
| FR02 | 业务配置 schema/存储/UI/品牌映射归业务插件；Harness 不导入这些实现 |
| FR03 | brand identity、安装版本、adapter 版本、能力证据分开；别名只能规范化为已有身份 |
| FR04 | 配置支持度按品牌×版本×入口×作用域×操作报告；发现品牌不等于能力可用 |
| FR05 | Profile 先解析有效配置；Harness 只接收已验证的业务片段与来源修订，不认识 Profile 内部结构 |
| FR06 | 配置与发送通过同一会话提交闸门；选择不应用，输出结束也不应用，下一次显式提交才应用 |
| FR07 | 应用操作 plan/apply/reconcile/query，明确 confirmed/refused/unknown，幂等键绑定调用方/目标/内容 |
| FR08 | 同一会话不同 generation 隔离；陈旧计划、晚到回执不能覆盖新状态 |
| FR09 | 整体配置先完成校验/冲突/隔离预检，再产生任何写入、spawn 或 ACP 设置帧 |
| FR10 | 一份原生文件只有 Harness materializer 执行写入；业务提供者产出声明，不自行碰用户文件 |
| FR11 | set/reset 的删除和默认语义明确；不把“省略”当“保留旧配置”，不默默忽略不支持字段 |
| FR12 | provider/model 与 Skill 至少各接入一个真实生产消费链；三主品牌要求见 SC03 |
| FR13 | 单会话变更不得污染别的实例、其他原生会话或全局配置；不能证明隔离则拒绝 |
| FR14 | 重启恢复由 runtime adapter 决定；成功确认原会话身份与有效配置后才放行消息 |
| FR15 | 资源租约/execution 沿用 Pacthold；配置流水不替代执行账本，不每条消息创建 execution |
| FR16 | 一个通道只有一个协议控制所有者；桌面不接收密钥，不创建第二套 ACP 客户端抢响应 |
| FR17 | 插件缺席/卸载、busy、异常清理均有定义；主异常不被清理异常覆盖，未清理事实保留 |
| FR18 | 迁移原有消费者，删除旧实现/重复注册/shim；entry point 与磁盘标识按迁移纪律保留或获批迁移 |
| FR19 | 公开 API 可独立安装导入；插件不导入 apps/server 实现，核心不导入 Harness |
| FR20 | 提供受控测试与逐 ID 基线差分，证据绑定提交及运行 pin，不拿 mock 当真实原生证据 |

## 非目标

本批不实现全部十二类配置的管理插件，不新增 sandbox 执行环境，不做跨 Harness 换会话，不修改用户已有 HOME，不重新发明 ACP/进程监督器，不升级全部上游 Harness，不建设派工/Skill 策略引擎。真实付费模型测试仍需独立授权。

## 成功条件

- SC01：新增测试用配置适配插件，Harness/Server/Pacthold 源码零变更即可完成注册、预检、应用、读回与卸载反例；新增测试用品牌同样成立。
- SC02：迁移清单中本批旧入口、跨域反向 import、全局配置写入、生产假成功 fallback 为零；原有受支持链路无未解释退化。
- SC03：Pi/Codex/Claude 各完成 model/provider 与 Skill 启用→变更→移除的受控生产链验收；每格明确版本、入口、隔离和恢复证据。某格做不到则本批不标完整完成，不以隐藏按钮代替要求。
- SC04：双会话隔离、下一次提交生效、崩溃/超时/取消、缺席与卸载等 verification.md 的必需门全部通过。
- SC05：目标平台基线和各包精确 SHA 已冻结，数量、失败 ID、失败原因、收集错误分别报告；无真实模型费用。

## 假设与边界情况

默认面向本地受控进程，凭据只通过已有秘密服务引用；远程/Windows 的未测能力不宣称可用。配置根隔离不是 OS 安全沙箱。已进入模型上下文的指令不能“撤回记忆”；移除 Skill/提示配置只控制后续加载，不承诺删除既有历史。授权策略不可被 Profile 降级，声明的可配置性不等于安全授权。

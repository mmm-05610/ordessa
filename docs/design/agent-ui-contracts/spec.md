# Feature Specification: 可替换的领域 UI

Created: 2026-09-27 | Status: Draft for review | Implementation branch: 尚未分派

## User Scenarios & Testing

### US1 — 业务作者消费组件接口（P1）

业务插件作者传入数据与回调即可使用组件，不导入提供者实现。
Independent Test：两个分别构建的受控扩展，一个提供简单卡片，一个消费；无 Agent、Workbench、Server。

1. Given 产品选定 A，When A 和消费者加载，Then 显示 A；反转加载顺序结果相同。
2. Given 消费者未改动，When 下一次装配选择 B，Then 显示 B，A 不被渲染。
3. Given 只安装契约且未加载提供者，When 消费者导入 API，Then 导入成功，无隐式激活。

### US2 — 卸载、缺席与错误可区分（P1）

Independent Test：同一宿主、同一 React 根，加载→卸载→重激活→消费者卸载。

1. Given 必需组件已显示，When 提供者卸载，Then 旧视图退出、旧动作回调失效、显示缺席提示；受控后台运行未被取消。
2. Given 可选配置展示提供者卸载，Then 隐藏该区，保存数据不变；重激活后显示新实现。
3. Given 提供者渲染抛错，Then 仅该消费位置报错、其他位置继续；不能按“可选缺席”偷偷隐藏错误。

### US3 — 装配者明确控制选择（P1）

Independent Test：多提供者、缺指定者、重复项、版本不符四种产品组合。

1. 未指定选择或指定者未到：明确缺席，不自动选择唯一已注册者。
2. 同一接口下相同 providerId 重复：拒绝整个新注册批，旧提供者保持。
3. 同一接口可登记不同 providerId；只消费产品选中的一个，其他实现不挂载。
4. 替换配置只在重新装配时生效；v1 不开放运行中修改接口，修改原输入数组不能影响已冻结的选择。

## Requirements

- UI-01：平台 MUST 无 Agent/Profile/模型/审批领域导入或硬编码组件 ID；领域 API MUST 不导入实现入口。
- UI-02：接口使用单实例、类型安全的 key；同名重复构造 MUST 被识别，不能靠字符串偷偷连接。
- UI-03：选择 MUST 属于单宿主实例、装配时冻结；双宿主互不影响。
- UI-04：注册 MUST 由资源作用域持有，批次先验证后发布；失败、重复 dispose、过期 handle 不得伤及新注册。
- UI-05：消费绑定 MUST 属于消费者作用域，只能读取本组件快照与订阅，不能枚举或修改其他提供者。
- UI-06：快照 MUST 区分 ready、missing、disposed；ready 有实例代次。渲染错误按消费位置记录，不把整个提供者宣判失效。
- UI-07：解绑/卸载后旧受保护动作 MUST 拒绝；已被业务接纳的异步工作继续按业务自己的生命周期处理。
- UI-08：错误边界 MUST 隔离渲染/生命周期错误；异步动作必须单独处理。不得记录完整 props、消息或密钥。
- UI-09：必需位置缺席显示提示，可选位置缺席隐藏；有实现但报错可见。不得自动回退到旧实现。
- UI-10：受控 props 拥有草稿/审批/配置状态；UI 不能自行宣布发送成功、审批成功或配置应用成功。
- UI-11：产品 MUST 在激活完成后检查必需组件，输出明确诊断；无业务要求的空宿主正常。独立插件失败不阻止无关功能。
- UI-12：真实构建 MUST 证明 React/key 单实例、契约独立可导入；使用现有共享模块机制，不增加业务契约总包。
- UI-13：仅渲染受信任扩展提供的 React 组件；API 类型与 ErrorBoundary 不构成代码沙箱。
- UI-14：常规业务注册位置继续归 Workbench/Chat/Profile；通用 UI 机制只选择与渲染实现，不取得这些位置的业务所有权。
- UI-15：领域 API MUST 按 component-catalog.md 覆盖五组、12 个组件及共同的动作/加载/选择/错误表达；契约覆盖与实现完成分别记录。提供者只注册已实现接口。
- UI-16：复杂组件 MUST 接受受控子内容渲染入口或轻量组合 helper，使工具/审批等子组件可独立替换；无子实现时保留说明并禁用交互，不静默丢失信息。

## Success Criteria

- SC-1：添加受控 UI 提供者和消费者时，平台/Workbench/应用源码修改数为 0；产品装配清单可改。
- SC-2：A/B 替换中消费者实现改动数为 0。
- SC-3：缺席、卸载、重激活、批次回滚、旧回调、双实例、重复 key、渲染异常均有可失败反例。
- SC-4：现有前端测试 ID 无未解释丢失；新增包纳入真正执行的聚合门禁。
- SC-5：Profile、model-provider、Skills 和未来工作面板的组件需求在总览中有明确归属；增加这些领域组件不需要增加平台专用分支。

## Edge Cases / Non-goals

必需者迟到、仅可选者缺席、卸载与点击同轮事件、卸载后重激活同 ID、激活失败撤销一部分贡献、同名 key 复制、卸载消费者先于提供者、React StrictMode、异步动作完成于视图卸载后。

v1 不实现运行中换选定提供者、跨框架组件、任意代码隔离、通用表单 schema 引擎、组件市场、自动加载所有已安装提供者。

状态：**研究第一版，供分类与边界审阅；不是实施授权，也不是八种 Harness 已验证能力声明。**

查询日期：2026-09-27。范围以 Ordessa 注册表中的 Codex、Claude Code、Pi、Hermes、OpenCode、dsh、Qwen Code、Kilo 为准。没有修改产品代码、切换分支、启动 Harness、读取用户配置或调用真实模型。

## 本轮得到的结论

可配置面远多于 model、Skill、MCP。至少需要覆盖：推理参数、指令/人格、按需知识与命令、工具目录、外部服务、权限、原生隔离、Hooks、原生扩展、子代理、记忆与压缩、运行环境，以及容易漏掉的隐私/遥测/更新/界面偏好。

但“能改变”不意味着“应存入 Profile”。要分别处理：

- **预设内容**：用户选择的模型、启用哪些资源、允许哪些能力、预算等。
- **被引用资源**：Skill 包、MCP 定义、提示词、Hook 脚本、模型供应商定义等；本体仍由其业务插件管理。
- **运行状态**：会话记录、压缩结果、生成的记忆、任务与进程；不是预设。
- **宿主/管理员约束**：安装版本、强制策略、端口、部署凭据、机器路径；普通 Profile 不能覆盖。

最值得统一的不是八份原生配置文件，而是**资源引用、可用性验证、作用域、生效方式、应用证据与安全边界**。原生语义必须保留。

## 精确性边界

“官方支持某字段”与“Ordessa 可以把它应用到这个正在运行的会话”是两条独立结论。本轮主要建立前者的资料索引与分类，不把官网的 CLI/TUI 功能直接推定成 ACP 能力。

官方网站不提供一个能枚举任意第三方扩展全部配置的封闭全集；本版没有把所有环境变量逐个解释、没有完成每个字段的最小版本和热更新实测。相关剩余项明确列在 sources-and-gaps.md，不能把本版直接交给无人值守代理当“所有支持已确认”的实施规格。

`agent-config-inventory` 仅用于提醒检查类别；它的旧实验、路径和结论不作为事实证据。本轮采用 OpenAI 官方文档查证要求处理 Codex，其他品牌同样优先官网与官方仓库。没有执行该 inventory skill 的旧版 agent-box 实验流程。

# Feature Specification：ZCode 风格的 Chat 展示

状态：v2 产品设计定稿；尚未指定实施基线/分支。前置：C7/C8 通用 UI 平台通过集成审核。US4–US7 及创建/输入增强需求见 input-spec.md，属于本批完整交付范围。

## User Stories

### US1（P1）：阅读 Agent 输出与思考

Agent 正文是可阅读的全宽文本，不是每段套大框；用户输入与助手输出有清晰层次。思考默认收起，用户可自行展开且不被后续状态更新强制收起。

验收：流式 Markdown 逐步完成；已完成历史按静态模式渲染；代码、列表、表格、中文混排可读；主题切换不丢正文；未知/中断状态不伪装完成。思考运行态仅表明该内容正在输出，不作为整个 execution 的终态。

### US2（P1）：快速看懂工具调用，需要时深入

默认是“图标 + 操作类型 + 目标/命令摘要 + 状态”的紧凑行。展开显示输入、结果、错误。多个工具不会把聊天区变成满屏大卡片。

验收：摘要可键盘展开；嵌套文件操作按钮不双触发展开；输出更新不覆盖手动阅读位置；暂停跟随后有明确新输出/恢复跟随入口；失败原因可用键盘查看，不仅存在于 hover tooltip。未知工具仍显示可读标题及原始文本，零内容丢失。

### US3（P1）：正常对话能力不因美化退化

验收：底部输入区不随消息列表滚走；中文输入法不误发；拒绝/未知发送结果保持草稿；停止请求不是停止成功；过期审批不可操作；切换会话不串消息/折叠状态。相关业务判定仍来自现有服务，不由移植 UI 重写。

## Requirements

- R01：research-plan 中源文件/逻辑逐项移植或明确适配，保留版权、许可、修改说明；不能只以“参考 ZCode”交付自写替代品。
- R02：展示组件只消费只读 DTO、受控状态和明确动作，不直接调用 Server/ACP/文件系统，不导入 ZCode store/services/protocol。
- R03：默认样式对齐本方案：助手无大背景卡片、思考低强调、工具紧凑摘要；使用 Ordessa 主题和平台基础件，不全盘替换工作区设计。
- R04：本地展开/滚动状态按会话+内容 ID 隔离且随视图回收；不得复制上游无限增长的模块级 Map。
- R05：正文 Markdown 与工具纯文本分别处理。日志默认文本，不因内容形似 Markdown 就执行富渲染；HTML/危险 URL 不执行；远程资源不自动请求。
- R06：Chat 自己拥有展示扩展面；平台不认识 tool/approval/model 等字段。业务插件通过公开轻量契约接入，不能 import Chat 实现/store。
- R07：原服务语义、磁盘 ID、传输/会话引用不因 UI 改造改变；真实能力缺席不通过猜工具名补造。

## Success Criteria

1. 正文、思考、命令工具、通用工具四组都有“原来源→移植目标→保留行为→适配差异→截图/测试”证据。
2. 同一受控消息序列在深浅主题、360px/768px/1280px 容器可读；命令长行只在自身区域滚动；键盘可触及所有动作。
3. 流式输出/手动阅读、静态历史、同名跨会话工具、卸载重激活、审批失效都有反例；原业务测试无未解释退化。
4. 独立展示 fixture 不加载真实业务服务即可运行；产品接入另有真实构建证据，不能以 gallery 代替。

## 暂不包含

ZCode 工作流/子 Agent 编排、撤销工作区、对话共享、反馈服务、浏览器/CUA、Mermaid、Office/PDF 预览；本批不凭 UI 复用承诺这些功能。Git Diff 专业组件由所属插件提供；没有该组件时显示原始变更文本，不能静默丢块。

# Feature specification

## 用户故事

### US1 / P1：管理可复用内容

用户在设置中创建“中文简洁回答”指令、编辑保存、复制、归档和导出。Given 原内容已被 Profile 引用，When 保存新修订，Then 历史修订仍可读取，原引用未断裂；归档不让既有会话失效。可独立用内容服务+管理页验收。

### US2 / P1：给 Profile 选择内容

用户选择多份补充指令并排序，选择至多一份人格；可在此新建专用内容。Given 尚未点“保存内容并选用”，When 取消内容弹窗，Then 不产生记录。已显式保存的内容不随随后取消 Profile 而删除，Profile 绑定则不变。可独立用 Profile 贡献夹具验收。

### US3 / P1：同会话下轮生效

Given A 正输出、B 同时运行，When 修改公共正文或切 Profile，Then A/B 当前输出不变；下一次各自提交按其 Profile/覆盖规则解析，冻结不同快照，应用确认后才发送。不能只验证 DB 值。

### US4 / P1：不同 Harness 不被强行等同

Given 目标支持追加、不支持系统替换，When 编辑 Profile，Then 只呈现有据可用的入口；保留的未知配置不丢，实际应用必须拒绝无法执行的片段。不能把替换默默改成追加，也不能用一条普通用户消息伪装系统配置。

### US5 / P2：检查实际装载内容

用户按需预览 Ordessa 将交给 Harness 的内容、来源和修订。预览不执行、不发送、不触碰项目文件；名称明确为“Ordessa 配置预览”，不声称展示模型完整系统上下文。

## 功能需求

| ID | 需求 |
| --- | --- |
| FR01 | 三种不可混淆用途 instruction/persona/system-replacement，同一业务域内管理 |
| FR02 | 正文不可变修订、元数据 CAS、内容摘要，明确空白/编码/容量规则 |
| FR03 | 公共内容及 Profile 专用内容，后端授权隔离，不按 UI 隐藏代替授权 |
| FR04 | 默认 latest 引用；一次提交原子解析多份 latest 并冻结确切修订 |
| FR05 | 补充列表有序且不重复；人格/替换各至多一项；item 覆盖遵循 Profile |
| FR06 | 归档不破坏已有引用，不硬删除；复制生成新 ID，不共用可变记录 |
| FR07 | Settings 管理、Profile 配置 facet/编辑器、Harness adapter 分别注册；缺席不崩其他功能 |
| FR08 | 业务逻辑不写原生文件、不建 ACP 客户端、不调用模型、不重启进程 |
| FR09 | 无表达式求值、shell、递归 include 或自动远程下载；原生隐式展开不可控则拒绝 |
| FR10 | 追加、人格、替换分别探测支持；只修改本插件拥有的原生目标 |
| FR11 | 移除/切换生成完整 reset；不保留上次已移除的文本、不重复叠加 |
| FR12 | 下次显式提交才应用；失败/unknown 不清旧会话覆盖、不发原消息 |
| FR13 | 项目原生指令只读，不自动修改、屏蔽或复制；优先级影响必须可诊断 |
| FR14 | Markdown 预览无脚本/危险 URL/自动远程图片加载；内容不进普通日志 |
| FR15 | 导入复制正文，导出通过用户选择目标；不接受远端客户端任意宿主路径读写 |
| FR16 | 三主品牌补充指令受控产品链通过；其他语义按版本证据提供 |
| FR17 | 隔离装包、按失败 ID/原因回归、公开依赖检查；不把夹具绿当原生确认 |

## 非目标

不做 Skill 仓库、slash 模板参数、原生 subagent、内容市场、团队实时协作、自动提示优化、文件 watch、记忆系统或权限策略。自然语言限制不等于强制权限。关闭指令不承诺清除历史对话中的影响。

## 成功条件

- SC01：独立 Prompts 管理无需启用 Profile/Harness；启用后通过注册得到相应入口。
- SC02：共享/专用内容的保存、引用、取消、归档、并发冲突均有反例；无人需要复制正文进 Profile DB。
- SC03：Pi/Codex/Claude 的补充指令启用→编辑→排序→移除走真实 Ordessa 应用链及固定原生加载入口，受控无真实模型费用。
- SC04：G01–G22 必需门通过；品牌未知矩阵、未测平台如实报告，无宿主改动、无旧链兜底。

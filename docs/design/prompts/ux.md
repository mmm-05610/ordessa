# Frontend and interaction

采用现有 Ordessa Workbench/Settings 布局、主题 token 和字体。frontend-design 的检查用于信息层次、可操作错误和键盘交互；不另配一套色板/字体或装饰动画。页面唯一任务是管理正文与使用关系。

## 设置：指令与人格

```text
指令与人格                           导入   新建
搜索…    全部 / 指令 / 人格 / 系统替换    显示归档
────────────────────────────────────────────
内容列表             │ 名称 / 用途 / 所属范围
中文简洁回答         │ 正文 [编辑 | 预览]
审阅者               │ …
…                    │ 修订历史   复制   归档   保存内容
```

宽视图列表+编辑区；窄视图列表与详情切换，返回保留列表位置。无独立全局侧栏、不挤进 Workbench 项目树。首版使用平台 Textarea；键盘快捷保存只作用于当前编辑器，不抢全局命令。

内容库默认显示公共内容；切到“Profile 专用”后选择获准 Profile，按 Harness→Profile 定位，不复制 Profile 管理导航服务。用途创建后不可改，提供“复制为其他用途”。无内容时给“新建内容/导入 Markdown”，不摆占位统计。

编辑不自动保存。存在其他 Profile 引用时编辑区说明“保存会更新引用此内容的配置，运行中的输出不受影响”；不声称已枚举全量引用，引用数量只有能从公开索引准确取得时才显示。保存冲突保留本地草稿，提供查看新版本、复制草稿，不强行覆盖。

Markdown 预览关 raw HTML/脚本、危险 URL、自动远程图片加载；外链由平台外部打开确认机制处理。不把渲染失败当内容丢失，文本模式可用。

## Profile：指令与人格

延用 Harness→Profile 两级导航，在所选 Profile 的“指令与人格”区呈现：

- 补充指令列表：选择、移除、上移/下移、预览；拖拽只是可选增强，键盘按钮必须有。
- 人格：单选+不设置；真实支持该能力才显示。
- 系统替换：折叠高级区、单选+不设置，注明替换原生默认行为，不替代安全策略。
- 新建：弹窗选择公共/该 Profile 专用，默认专用；两个独立保存动作遵循 data-model.md，不伪装跨库事务。

选择器显示名称、说明、用途；公共和专用来源明确区分。列表中隐藏归档，但已选归档内容保留行及归档文字，仍可预览/移除。引用缺失/越权是明确错误，不能静默变成未选。

系统替换的风险说明在高级区常驻一行，不给每次会话切换弹确认框。授权拒绝由后端执行，UI 勾选不能提升权限。

## 缺席与异常

- Prompts provider 卸载：Profile 区隐藏，原数据不删；运行应用仍校验缺席。
- provider 存在但请求失败：本区显示错误+重试，保留选择/草稿，不整页清空。
- 切 server/profile 或提供者代次改变：取消旧请求，晚到结果不能落到新目标。
- 离开未保存内容：复用平台确认浮层；确认只针对编辑器 dirty 内容，不拦用户正常选择 Profile。
- 焦点、Escape、Tab 圈、返回焦点由平台 overlay 负责；测试贡献层没有破坏它们。

不新增 Chat 常驻 selector、pending/current/modified 标签或“人格已应用”虚假 toast；Chat 继续只操作 Profile。

# 设置、项目、Profile 与 Chat

## Settings：Skills

一个设置入口包含“内容库”“默认启用”“项目启用”。沿用平台 Panel、Toolbar、列表、Field、Dialog、滚动区、焦点行为，现有 Skills 页面可保留列表和预览组件；不新增全局侧栏或 Assets 总导航。

- 内容库：来源、摘要、已批准版本、更新候选、diff、附件/脚本清单，导入先预览再发布。公共/项目/Profile 专用归属清楚标记。
- 默认启用：先选“所有 Harness”或某品牌，逐 Skill 选择启用/禁用/继承；每项显示固定版。页面说明全局默认仅影响当前用户在本 Server 中的新提交。
- 项目启用：先经 Workspace 选择项目，再选所有 Harness/某品牌；显示继承自全局的结果和本层例外。项目消失/无权时停止编辑，保留已存记录待项目恢复或显式清理。

同一列表不能用一个总开关误导：每行显示“本层设置”和“最终结果”，后者给出决定它的范围及版本。离开编辑草稿沿用平台 overlay；保存 CAS 失败保留用户修改并提供重读。

## Profile 编辑器

当前 Profile 所属 Harness 已确定。逐 Skill 三态“继承/启用/禁用”，可以看最终结果；启用时指定已批准版本，更新时先看差异。Profile 专用 Skill 可就地导入，内容在 Skills 库归这个 Profile，随后选择关系作为 Profile 草稿保存；取消 Profile 不自动删已经明确导入的内容。

移除 Profile 的覆写即恢复继承，不等于卸载内容或全局禁用。Profile 切换的会话语义遵循现有 Profile 方案：输出中选择只更改期望，下次用户输入前生效，旧覆写在成功切换后清掉。

## Chat `/` 与 `+`

菜单展示当前会话的受管已装载 Skill：名称、简介、来源、品牌及调用状态。浏览详情不发送消息。明确支持原生显式调用的提供“使用此 Skill”并由会话 owner 提交；只支持自动发现的显示“可自动使用”，不给虚假调用按钮。

如果当前 Profile 变更还未应用，菜单可显示选择后的预期项，但必须标明“下次发送后可用”；不能让点击旧运行时不可用项强行发送。下次提交完成后以新 generation 的已确认集合刷新。`/` 命令与 Skill 名冲突，使用命名空间或只读浏览，不覆盖已有系统命令。

## 原生发现和错误

原生发现项单列“由 Harness 或项目提供”，只读，包含来源类别，不擅自显示“启用/禁用成功”。用户可显式导入成新的受管副本，但原生项仍存在；重名时提示先消除冲突。没有独立装载证据时写“已投放，未确认装载”，而非“已启用”。

加载失败留原选择草稿、提供重试/诊断；缺业务 UI provider 时隐藏它贡献的 Profile 区，已存分配保留，后端应用仍拒绝缺失 adapter。退出确认、键盘上下移动与焦点恢复沿用平台控件。界面不展示原生绝对路径、密钥或脚本输出中的秘密。

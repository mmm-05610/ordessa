# Feature specification

## 用户故事

### US1 / P1：一份内容，多处使用

用户从本地或 Git 来源导入 Skill，预览正文/附件/脚本及差异，保存固定版本。Given 已在两个 Profile 使用旧版，When 安装新版，Then旧版仍可读、两个绑定仍指旧版；只有显式批准更新的绑定改变。

### US2 / P1：全局与项目按 Harness 分配

用户让 Skill 对所有项目的 Pi 默认启用，却只在 `ordessa` 项目的 Codex 禁用。Given 真实项目身份和目标 Harness，When 解析下一次会话提交，Then得到确定的有效集合与每项来源，另一个项目/品牌不受影响。

### US3 / P1：Profile 调整默认值

用户在 Profile 中为某个 Skill 选择继承、启用或禁用，并添加 Profile 专用 Skill。Given 通用与项目默认项，When切换同 Harness Profile，Then Profile 的显式决定覆盖默认，当前输出不中断、下一次输入才应用。Profile 归档不直接删除内容。

### US4 / P1：装载真实且不会串会话

Given A/B 同时使用不同有效集合，When A 启用/更新/移除，Then A 的受控原生入口读取 A 的固定包，B 与用户全局原生目录字节不变。写入投影只计“已投放”；只有观察到目标版本加载才计“已装载”。

### US5 / P2：看见原生发现项

用户能看到该 Harness 从项目/用户目录自行发现的 Skill 及来源。此类项默认为只读观察；需要进入 Ordessa 管理时显式导入副本。对没有隔离禁用能力的原生项，界面不得显示“已禁用”。

### US6 / P2：在 Chat 找到可调用 Skill

当前会话已经确认可用的 Skill 可以通过 Chat 的 `/` 或 `+` 菜单浏览。只有品牌支持且验证过显式调用的 Skill 才提供“调用”动作；自动触发型 Skill 显示详情，不靠拼用户文本假装调用成功。

## 功能需求

| ID | 需求 |
| --- | --- |
| FR01 | 内容库存唯一 Skill 包、不可变修订、来源/摘要、附件和脚本清单 |
| FR02 | 本地/固定 Git 来源预览、批准、导入，默认不执行脚本或自动安装依赖 |
| FR03 | 内容归属为公共库/项目专用/Profile 专用，与分配范围分离 |
| FR04 | 用户全局/项目各有通用及 Harness 特定分配；每 Skill 显式启用、禁用或继承 |
| FR05 | Profile 贡献同一套三态，按稳定身份引用固定批准修订；会话覆盖依 Profile 规则 |
| FR06 | 按确定顺序解析，不因 native 文件夹层级改变 Ordessa 的覆盖语义 |
| FR07 | 新版发布不自动移动已有绑定；逐范围显式批准升级，可预览 diff |
| FR08 | 应用前冻结集合/版本/项目及 Profile 修订，失效/冲突在任何原生写入前拒绝 |
| FR09 | 管理和运行采用同一用户/服务域鉴权；客户端不能冒领项目或 Profile |
| FR10 | 原生 Skill 独立观察；冲突或无法禁用有明确诊断，不静默覆盖 |
| FR11 | Harness 配置适配器按品牌/版本/入口声明装载、撤销、重载和核验能力 |
| FR12 | 运行投影由 Harness 持有；任何受管写入不修改用户 HOME 或仓库原生 Skill 目录 |
| FR13 | 区分 stored/selected/projected/loaded/used/unknown，不能把摘要一致当装载或使用 |
| FR14 | Settings、项目、Profile、Chat 入口都经各自注册点，业务插件不依赖宿主内部实现 |
| FR15 | 现有资产 ID、摘要算法和历史绑定保留或按已审迁移处理；旧入口只留一套实现 |
| FR16 | 受控三品牌产品链、双会话隔离、版本升级和原生发现冲突均通过反例 |

## 非目标与成功条件

本包不建立 Skill 工作流引擎、执行策略或跨 Agent 派工系统；Skill 描述的工作方式仍由正文决定。项目导出为显式独立操作，首版不自动写 Git 仓库。可执行脚本的授权仍由现有工具/审批机制负责；`allowed-tools` 或原生 Skill 元数据不得自动提升权限。

完成要求：公共库可独立管理，四层分配真实可用，Pi/Codex/Claude 的受控加载链至少覆盖启用、更新、移除；未知品牌只给已证能力。各必需门禁、产品构建与逐失败 ID 同因回归通过。真实模型调用不在本包授权内。

# 信息收集优先级路径（主会话/侦察用）

状态：**v1 定稿（2026-09-28）**。解决的问题：agent 从互联网收集信息常遇到
**滞后**（官网写的不是已发布的）、**不全**（单源漏面）、**不准**（第三方转述
失真）。本路径给出信任顺序、失效处理与记录要求；一切盘点/侦察/方案包设计
必须遵循。与 sources-and-gaps.md 的证据规则同源，此处上升为通用路径。

## 一、信任阶梯（从高到低，高级与低级冲突时高级胜）

| 级 | 来源 | 信任前提 | 典型坑 |
| --- | --- | --- | --- |
| L1 | **仓内固定事实**：版本 pin、锁定快照、已冻结契约（SHA） | 本仓维护 | 只有对现状有效，对外部新版本无效 |
| L2 | **目标版本官方源码 / 官方 Schema**（钉 commit） | 能固定 SHA | 主分支≠发行版，需标注 |
| L3 | **官方文档**（记录抓取日期） | 官方域名 | 滞后于代码、实验特性混入、版本未标 |
| L4 | **官方 issue / release note / changelog** | 官方仓库 | 回复可能是计划而非承诺 |
| L5 | **一手受控观测**：探针/假端点/回读（E2 级） | 可复现、留痕 | 环境差异；不可外推版本 |
| L6 | **第三方 inventory / 博客 / 历史对话 / 训练记忆** | **仅作线索**，不作证据 | 失真、过时、张冠李戴 |

**硬规则**：L6 内容必须升级到 L2-L4 证据才可写进任何方案包；记忆里的"我记得"
按 L6 处理。

## 二、三类失效的处理法

1. **滞后**（官网说的是将来/过去）：一切"当前"声明钉到固定 commit 或 release
   tag；主分支与发行版不一致时分开登记（sources-and-gaps 先例）。
2. **不全**（单源漏面）：关键结论双源交叉（源码 ∨ Schema ∨ 文档 至少两类）；
   覆盖度用计数口径自查（如 collect-index 的逐文档条目数），不冒充穷尽。
3. **不准**（转述失真）：引用必须落到 L2-L4 原文（URL+日期+commit+必要时
   SHA-256）；第三方说法与官方冲突时只信官方，并把冲突记录在案。

## 三、收集顺序（方法路径）

1. 先问 L1：仓里有没有已钉版本/快照/既有盘点 → 有则只做增量核对。
2. 没有 → 锁定官方仓库：取 main HEAD 与最近 release tag，**分别**记录。
3. 按"配置入口 → 扩展面 → 通道（CLI/RPC/ACP/SDK）→ license → 安全面"顺序
   读官方材料，每条记 URL/日期/commit。
4. 文档与源码冲突 → 以源码为准并登记差异；探针只用于二者都答不了的点（E2）。
5. 产出落 `docs/design/<主题>/` 或 specs 包的 plan facts，缺口如实标"待核实"，
   不允许"看起来支持"。

# UX：轻量选择、透明拒绝、真实审批

## Settings

两个独立设置区按实际后端贡献出现：**权限与审批**（规则来源、组织上限只读摘要、用户默认意图、审批历史过滤）和 **Harness 原生隔离**（各品牌/平台可用原生能力、覆盖范围、原生配置诊断）。没有对应提供者则隐藏，不留故障占位；服务在但加载出错时显示局部错误，不伪装未安装。

管理员上限只能由管理员受控入口编辑；普通设置页显示“该项由组织/宿主限制”并拒绝提升。没有可信上限记录的非管理环境可以沿既有原生 Harness 默认运行；但若某组织明确要求强制策略、加载失败不得静默沿用宽松默认。`full access`、`auto`、`YOLO`、`bypass` 不做跨品牌同义标签；品牌选项以真实官方描述和覆盖工具列呈现。

## Profile 编辑页

两个插件分别注册 Profile Facet。权限 Facet 可保存工具选择/需审批的用户意图；原生 sandbox Facet 可保存“目标隔离要求”，并显示“涵盖 Bash/文件工具/网络”的实测范围。编辑只改草稿与预设版本，不直接放行任何工具、不改管理员上限或全局用户 Harness 配置。缺插件时对应设置项隐藏、值保留；下次应用仍需后端重新验证。普通会话内 Profile 切换只调整下轮待提交的意图，不中断输出。

## Chat

输入区可以显示一个简短的该品牌模式选择入口，但**不**合并“权限”“原生 sandbox”两个维度为一颗万能按钮。点击选项后正常情况不要求展示多层状态徽章。待审批时在消息附近展示真实操作类别、目标、权限来源与可选范围；允许一次、允许范围、拒绝清楚分开。审批卡绑定后端 approvalId/version，失效或跨会话切换后自动不可操作；按按钮后先显示“待确认”，直到后端及 native owner 收据确认才显示“已决定”。断连时禁“允许”动作，提供恢复/查询而不是暗地重发。

## 文案和可访问性

拒绝时写明“哪个目标/动作被哪一层限制”，但对路径/参数/秘密脱敏；未知时说“无法证明生效，未执行”，不说“安全模式已开启”。键盘焦点、ARIA、撤销/过期反馈复用现有 Workbench/agent-ui 组件与通用浮层；不在这两个业务域复制对话容器或基础 Popover。无 UI/headless 场景由后端执行同一拒绝/审批语义。

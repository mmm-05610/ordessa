# Feature Specification：Profile v2

状态：待审核。已确认行为继承旧 001-profile；新增政策/界面默认值是本提案，不自动生效。

## 已确认不变式

- 一个 Profile 只属于一个 Harness；不跨 Harness 切换/复制，不自动换所属 Harness。
- 会话有效配置 = Profile 最新修订 + 会话逐项覆盖；会话修改不反写 Profile。未覆盖字段在下一轮跟随更新。
- 成功显式切换另一个 Profile 时清除全部会话覆盖，不额外提示；失败/未知不得清除。再次点击当前 Profile 不等于清覆盖。
- 提供者未加载时编辑项不显示，数据保留；不能因为界面缺席就伪称配置已生效。
- 本轮配置保持固定；切换在安全的下一轮边界，不打断当前生成。

## User Stories

### US1 / 配置机制设置（P1）

设置 → Profile 提供“配置提供者”和“会话修改规则”，不是预设列表。

- PS01 服务域内已注册配置提供者可启用/禁用；不等于卸载插件，不影响它的独立设置和非 Profile 能力。启用只开放配置面，不自动将能力加入现有 Profile。
- PS02 首版规则为“允许用户新增或修改会话临时覆盖”（默认允许，可按配置面限制）；限制后既有覆盖不被静默删除，仍可查看、清除。此设置不是安全权限吊销。
- PS03 Agent 自主切换/编辑不在首版开放，不摆无后端的开关。未来可接独立请求/批准机制，不用此规则隐式给 Agent 改配置权限。
- PS04 设置存于选定 Server 数据域，受认证与授权；前端隐藏不是 enforcement。不同 Server 不共享全局开关，页顶显示当前服务域。
- PS05 禁用前显示受影响 Profile/会话数量；确认后隐藏配置编辑区、保留值。运行轮不变；下轮若需要被禁用配置则明确阻塞，不静默放宽权限或使用默认值。恢复启用须重新校验。单纯卸载不弹多余配置卡，只在实际受阻操作处说明。
- PS06 Profile 自身设置页提供独立的设置项/设置区注册面，每个接入提供者均可贡献；与单个 Profile 的字段编辑注册分开。提供者拥有其设置语义、校验与持久化，卸载隐藏但不删数据；新增提供者不修改 Profile 页面实现。

### US2 / 独立管理器（P1）

- PM01 通过 Workbench 注册管理入口和主视图。编辑器内两级导航是 Harness → Profile 名称；服务域用上方选择器，不增加第三层。
- PM02 Harness 来源是后端目录；本服务已存但当前不可用 Harness 的 Profile 仍可读，不因发现失败消失。创建/应用按真实可用性拒绝。保存不依赖机器能跑模型，但需字段提供者存在且验证可用。
- PM03 创建空白或复制同 Harness；中文名称允许、名称不作路由键。建议新建/重命名时同一服务/Harness 下活动 Profile 名称按 Unicode NFC + trim + casefold 唯一，不同 Harness 可同名；旧重名数据不强改名，以稳定 ID 区分，后续重命名按新规则校验。
- PM04 显式保存，单次 patch + expectedRevision；并发编辑拒绝过期写，保留本地输入供比较。离开未保存页面提供保存/放弃/留在此处；这不等于切换 Profile 时的临时覆盖确认。
- PM05 首版只归档/恢复不硬删。归档禁止新绑定和新的切换，既有绑定固定归档时的 Profile 修订，仍需正常应用校验，不自动选别的；归档内容只读。恢复后下一轮重新解析；恢复遇活动名称冲突须先改名。归档有受影响提示，不把归档当作吊销运行权限。
- PM06 保存字段由提供者贡献，未加载不显示；空组不显示。Profile 基础元数据管理不依赖 model-provider/Skill/Chat。

### US3 / 内容是可组合能力，不是秘密仓（P1）

- PF01 模型、Skill、MCP、Hooks、Prompt、原生工具、审批/沙箱配置等是配置面例子，不是 Profile 硬编码必备字段。
- PF02 启用能力、允许执行/审批模式、指令建议必须区分。权限类字段显示执行方及实际 enforcement 等级，不能把 prompt 写法显示为强制禁止。
- PF03 配置提供者拥有字段 schema/默认/校验/编辑器/编译；Profile 拥有值与修订/覆盖。资源正文、凭据、MCP 进程与 Harness 文件不由 Profile 存管。
- PF04 数据模型必须区分 unset（交给目标默认）、explicit null/空列表（字段定义允许的明确空值）、disabled（业务显式关闭）、provider absent（未知），不能全部归一为空。
- PF05 基础校验通过但需要特定运行目标验证的配置可以保存，标“运行前验证”；静态错误不可保存；不支持的权限语义不可偷偷降级为提示词。

### US4 / 同会话切换与来源（P1）

- PA01 内部区分所选目标与最后确认生效值；界面选 B 后立即显示 B，含义为“所选 Profile”。不常驻显示当前/待生效/临时覆盖标记。无论空闲还是输出中，选择仅登记，在下次用户提交输入时应用；输出结束不自动应用，不能打断当前输出。
- PA02 两会话使用同一 Profile，只修改 A 模型不影响 B；全局修改另一个 item 仍进入 A。Provider/Model 如不兼容，阻下一轮并指出冲突，不能静默改 A 的覆盖。
- PA03 验证所有新增、修改和移除项；切到 B 不能残留 A 的配置。运行实现无法复位某项时拒绝，不能报整套切换成功。
- PA04 应用计划只允许同会话原生热切换或受证明的重启恢复；不需要创建全新可见会话。若重启导致新的 execution，旧 execution 终结不恢复，新 execution 关联原 conversation。
- PA05 无法证明完整旧配置或新配置时进入 needs-recovery，阻发送；显式核实/恢复，不自动重发消息。读回 Profile DB 不算运行证明。
- PA06 原有安全策略永远有效。更宽松 Profile 配置若需授权，走原审批；“无临时覆盖确认”不豁免授权确认。
- PA07 Chat 选择器采用 Harness → Profile 两级模型选择器式交互；草稿可选择初始 Harness，既有会话只提供当前 Harness 分组，不允许跨 Harness。实际应用失败才在发送操作处解释并保留草稿，不静默退回旧配置发送。

## 成功标准

三个独立组合均可运行：零配置面管理 Profile；有 Profile+两种受控配置面但无 Chat；有 Chat 的选择/覆盖/下轮生效。新增第 3 个配置面不修改 Profile 核心和两端宿主。双会话、双 Server 同名 ID、重启、卸载、部分应用失败和复位均有可观察反例。最终证据区分存储、UI、受控 Harness 和真实品牌验证。

## 非目标

Profile 继承树、跨 Harness 转换、Profile 内嵌会话/记忆库、全局切换原生配置目录、插件安装市场、权限引擎、自动 Agent 策略、云同步、打包导出凭据、全品牌任意配置都热切换。首版不新增默认 Profile 自动选择规则；新会话仍显式选择或沿已存在产品默认行为。

# Profile v2：能力配置预设与可扩展管理器

2026-09-27 · **完整实施设计包，待最终审核与平台起点绑定，未实施、未派发。**采用 Spec Kit 文档结构。旧实现与方案只读参考；本包不是对现存代码的验收，也不重写其他会话的计划。

## 审核摘要

1. Profile 是单一 Harness 的命名配置预设，不是账户、会话、进程目录、Skill 容器或安全沙箱。
2. 设置中的 Profile 页管“哪些配置提供者启用、哪些会话配置操作允许”，并允许各提供者注册自己的设置区；独立 Profile 管理器管预设内容。左侧两级导航严格为 **Harness → Profile 名称**。
3. 编辑页组织为概览/模型/能力/行为与权限/指令/高级；分类只是展示分组，实际字段由插件贡献。不存在的能力没有空占位。
4. 已批准语义不变：最新 Profile + 会话逐项临时覆盖；不反写预设；成功切换另一 Profile 后清覆盖且不提示；失败保留覆盖；运行中不改当前轮；不跨 Harness。
5. 保存预设≠应用到会话；数据库确认≠Harness 应用证明。Profile 解析目标配置，Harness 在既有运行接缝内实际应用并给出可核验证据；不新增“万能装配协调插件”。
6. 不把权限、模型、MCP、Skill 业务塞入 Profile 或平台内核；只管理配置面的注册、版本化存值、解析与会话绑定。
7. Chat 仅提供模型选择器式的 Harness → Profile 选择器：选择立即显示，下次用户提交输入时应用，不打断当前输出，不展示当前/待生效/临时覆盖等常驻标签；已有会话仍不跨 Harness。

需要用户审核的是本包的产品决策，尤其是：**显式保存而非逐次输入自动保存；首版仅归档不硬删；设置中禁用配置面不丢数据但会阻止依赖它的下一轮；首版不开放 Agent 自动切换 Profile。**这些为本提案的明确建议，不冒称此前全部批准。

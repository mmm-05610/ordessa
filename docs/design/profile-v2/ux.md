# UX：机制设置、管理器与会话入口

设计目标：像管理一套 Agent 工作配置，不像数据库后台。复用平台既有字体/主题/Panel/Form/Toolbar；轻量分隔、清晰状态与来源，不新创一套视觉系统。前端设计审阅重点是任务入口、信任状态和键盘可达性。

## 1. 设置 → Profile

```text
Profile                        服务：本地 Ordessa ▾

配置提供者
  模型配置                    已启用       [开关]
  技能                        已启用       [开关]
  MCP                         已启用       [开关]
  （仅列真实注册提供者）
  各提供者的设置区             （由对应插件注册，有内容才展示）

会话配置修改
  允许用户新增/修改临时覆盖                  [开关]
  配置面规则                  跟随全局 / 允许 / 禁止修改
  说明：不删除已有覆盖，也不绕过运行权限。

管理配置预设 → 打开 Profile 管理器
```

两个开关维度分别是配置面接入和编辑权限，不是允许运行 shell。禁用配置面要在保存机制策略前说明影响，不暗藏“禁用即数据清空”。未注册提供者不在这里伪造灰色故障条目；历史禁用规则可保留但不显示为空卡。

每个接入者还可在此注册自己的设置项/设置区，配置它如何与 Profile 配合；这与右侧管理器里“某一个 Profile 使用哪些值”的编辑器是两个独立扩展面。提供者自行定义字段、验证、保存和说明，Profile 只负责分组装载。独立资源管理（供应商凭据、Skill 仓库等）仍链接到其所属插件，不复制一套数据。插件仍加载但配置面被禁用时，其机制设置仍可查看和调整；插件卸载则隐藏对应区域，已存设置不删。

## 2. 独立 Profile 管理器

```text
Profiles                 服务：本地 Ordessa ▾
┌────────────────────┬──────────────────────────────────────────┐
│ 搜索               │ 开发助手                      复制 · ⋯   │
│                    │ Codex · 修订 12 · 已保存                 │
│ ▾ Codex         +  ├──────────────────────────────────────────┤
│   默认             │ 概览  模型  能力  行为与权限  指令  高级   │
│   开发助手  ←      │                                          │
│   代码审阅         │ 本配置启用哪些能力                        │
│ ▾ Pi            +  │ Skill 集       …（提供者的配置区）        │
│   日常             │ MCP 服务       …                         │
│ ▸ Claude Code   +  │ 原生工具       …                         │
│                    │                                          │
│ 显示已归档         ├──────────────────────────────────────────┤
│                    │ 有未保存更改             放弃   保存      │
└────────────────────┴──────────────────────────────────────────┘
```

管理器导航是页面内的 Master/Detail，不要求 Workbench 新增特殊树契约，也不抢 Chat 侧栏数据。入口可从 Workbench 模块导航、设置链接、Chat 选择器“管理”打开同一个 view。通过已有注册 API 实现；WorkBench 侧栏独立任务不受影响。

### 导航

- Harness 行展开/收起；+ 创建该 Harness Profile；Profile 行选择，菜单含重命名/复制/归档。移动焦点不自动保存或应用。
- 搜索名称保留 Harness 分组与来源；同名跨组可辨。服务离线保留已知列表并标最后同步/只读，不猜可用性。
- 首版创建：名称、可选用途描述、空白/同 Harness 复制来源。创建不启动 Harness、不复制凭据/会话/内存；资源引用复用、秘密引用仍需当前授权。
- 复制保留存值包括隐藏的配置面，不依赖前端可见字段重建，否则会丢数据；若含不兼容旧 schema，复制后如实待迁移，不自动启用运行。

### 内容区

- 分类为固定展示桶，但桶内字段与标题由注册配置面提供；无内容的桶隐藏。概览固定显示名称/用途/所属 Harness/使用范围与引用情况。
- 模型：Provider/Model 选择与参数；供应商凭据和目录管理用链接打开 model-provider 自己的设置，不在 Profile 重建。
- 能力：选择此预设启用哪些资源，提供全局管理入口；Skill 正文/版本、MCP 连接本体仍由各插件管理。
- 行为与权限：明确“功能可用”“执行需确认”“系统强制边界”；按 Harness 实际能力展示，统一分类不意味着统一策略语言。
- 指令：引用 Prompt/SOUL 类资源；若提供者允许内联文本，其 schema 明确，不能偷偷写系统文件。
- 高级：已有 Harness 提供者贡献的少量受支持选项，不提供无 schema 的 JSON 任意透传后门。

### 保存与状态

- 页面缓冲编辑、明确保存/放弃。保存成功展示修订与“关联会话从下一轮读取，临时覆盖项除外”，不是“全部会话已应用”。
- 字段错误就地；跨字段错误带可跳转项；并发冲突保留本地编辑并提供重新加载/比较，不自动覆盖远端。
- 离开脏页确认；显式切换运行会话 Profile 不因清临时覆盖弹确认，两种确认语义不能混用。
- 提供者卸载：立即卸其编辑器，持久数据不删；未保存字段缓冲留本地但不可提交未知提供者，相关保存被阻并解释，不丢内容。其他无关 Profile 可继续编辑。
- 支持但当前值非法：显示真实字段错误；根本没有加载：不显示故障占位。实际发送受阻时由操作状态给出原因和重新启用/安装的路径，不把错误假隐藏。

## 3. Chat 接入

输入工具栏只放普通选择器：`开发助手 ▾`。展开沿用模型选择器的交互结构，一级 Harness、二级 Profile，当前选择打勾，底部提供“管理”。同名用所属 Harness 区分，作用域仍为当前 Server。

草稿尚未绑定 Harness 时可从各可用分组选择；既有会话不允许换 Harness，选择器只提供当前 Harness 分组的 Profile，不把两级目录误实现为跨 Harness 切换。

选择 B 后按钮立即显示 B，表示用户的选择，不是“当前输出已经使用 B”的声明。不展示“当前使用 / 下轮待生效 / 本会话有修改”等常驻标签，也不要求打开状态详情才能操作。Profile 本体编辑不发生在这个选择器。

- 正在输出：只记录选择，不取消、不重启、不修改当前轮。输出结束本身也不触发应用。
- 下次用户提交输入：先应用最终所选配置，再发送该条消息；之前连续选 B、C，只应用最后的 C。空闲时选择也遵循同一规则。
- 成功切换：正常继续对话，清除旧临时覆盖，不确认、不额外提示。
- 实际应用失败：在发送操作处给出简短原因和重试/重新选择入口，保留输入，不偷偷用旧配置发送。所选项可以保留供修正，但不能显示成功通知。

内部仍区分所选配置与已应用配置，以保证下一次发送正确；不将内部状态机逐项投射成用户必须理解的界面。临时模型等修改不反写 Profile，来源查询可供诊断使用，不是选择器的必备展示。

Profile 选择器是 Profile 的 Chat glue 贡献。无 Chat 时管理器和 backend 正常；无 Profile 时 Chat 原生配置和发送正常，不强制建立空 Profile。零配置面也可选空预设，但只有可证明的默认复位才可用于清除旧运行配置。

## 4. 可访问性与布局验收

树左右键展开/收起、上下导航、Enter 选择，action button 有独立名称；折叠不能丢编辑器未保存状态。分类 tabs 采用既有可访问控件；错误摘要可聚焦并跳转字段。1280×800、900×600、200% 缩放；窄视图折叠导航为页面内切换，不增加第三级树；底部保存操作可达。异步返回核验服务/Profile ID/revision，不能把 A 的表单数据写进 B。

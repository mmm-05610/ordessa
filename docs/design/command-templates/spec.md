# Feature specification：可复用命令模板

## 用户故事与验收

| ID | 场景 | 验收结果 |
| --- | --- | --- |
| US1 | 用户建立“审查变更”模板，填写焦点参数并保存 | 内容版本可预览、修订不可变；保存本身不启用、不发消息 |
| US2 | 用户在全局、项目或某 Profile 启用模板 | 可解释有效来源、固定修订及冲突；其他项目/会话不被改动 |
| US3 | 用户在 `/` 或 `+` 找到当前目标可用模板 | 名称、用途、来源、参数提示清晰；内建/Skill/扩展命令不被遮蔽 |
| US4 | 用户填参数、看最终文本并插入草稿 | 插入后可编辑且不自动发送；原草稿内容和光标保持，明确取消无副作用 |
| US5 | 多品牌或无 Profile/无原生模板能力 | 通用 Chat 展开仍可用；不宣称 native installed/loaded；缺 Chat 时内容管理仍可用 |
| US6 | 用户改内容或项目/Profile 切换 | 已插入草稿不暗改；旧菜单请求/旧目标展开不能写入新草稿 |

## 功能需求

- **FR-01 内容实体**：保存稳定 templateId、名称、说明、参数 schema、正文修订、所有者、内容摘要、归档状态；服务端验证大小、编码、占位符和引用。归档不等于删除历史引用。
- **FR-02 显式性**：模板只能经用户显式选择/输入调用；不能按自然语言自动触发，也不能靠内容提升消息角色或工具权限。
- **FR-03 独立分配**：内容入库、全局/项目/Profile 启用与一次展开各自独立。全局含通用及 Harness 专用；项目也可通用/专用，Profile 最后覆盖；强制组织策略永远高于这些偏好。
- **FR-04 固定版**：启用指向批准的不可变修订。发布新版不更新启用，显式批准后只影响之后的菜单/展开；已有草稿字节不变。
- **FR-05 确定性展开**：有类型参数，严格校验必需/范围/长度；仅一次替换，不二次解释参数中的 `$`、`{{...}}`、斜杠、换行或 Markdown；输出大小受限并按用户所见字节发送。禁止计算表达式、shell、URL/file include、递归调用。
- **FR-06 预览与插入**：预览显示最终文本、来源和 revision，用户可取消；插入到当前有效草稿，不创建通道/会话/turn。提交走现有 Chat send，失败仍保留草稿。
- **FR-07 命名冲突**：stable namespaced id 不冲突；显示名同名时在菜单显示来源；与内建/原生/Skill/扩展 slash 名冲突时不得抢占路由。可用 `template:<name>` 命名空间，确切语法由 Chat 真实契约冻结。
- **FR-08 可用性**：目标 projectId/server identity/Harness/Profile 必须来自真实服务；无项目、权限不足、引用缺失、provider 卸载或版本未知分别给出原因，不过滤成假空列表。
- **FR-09 注入边界**：模板和参数都是用户级内容，不执行其中的 shell、动态上下文或工具动作；渲染按文本处理。不能声称可防止模型被恶意文本影响，权限系统仍是实际强制边界。
- **FR-10 可选 native 投影**：只有品牌 adapter 在固定版本证明与“用户消息展开”语义等价、可隔离、可撤销、无同名双加载时才投影；否则 Chat 路径正常但 native 状态为 unsupported/unknown。
- **FR-11 作用域安全**：服务鉴权注入 principal，项目需授权；Profile 专用模板正文仍在本域且不可跨 Profile/Server 引用；CAS+幂等键防并发覆盖。
- **FR-12 生命周期**：scope 卸载撤销菜单/配置贡献；已有内容与展开记录保留。展开过程中提供者卸载、会话切换或修订失效必须拒绝落新草稿。

## 明确排除

Skill 包及自动触发、可执行扩展命令、原生内建控制命令、持久系统/开发者提示、递归模板语言、远端模板市场、自动扫描用户 HOME/项目原生命令目录、任意文件/网络动态上下文、付费真实模型测试。若原生项目目录本就包含同名命令，不能由 Ordessa 假称已将其禁用。

## 成功条件

三品牌 Pi/Codex/Claude 的 **Ordessa Chat 用户消息展开→受控 ACP 对端收到相同字节**，固定版/目标隔离/冲突/失效反例全部绿；原生投影按能力矩阵单独计，不拿 Chat 通路冒充品牌原生能力。受影响套件与既有红账本逐 ID 同因比较，干净装包和 UI 键盘/IME 门通过。真实模型调用未获授权时不计本批验收。

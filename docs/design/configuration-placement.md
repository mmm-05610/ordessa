# 配置落点规则：Settings / Profile / 会话区 / 资源库

状态：**规则定稿 v1（2026-09-28，与用户梳理确认）**。此前散在
profile-implications.md、classification.md、各方案包里的裁定在此收拢为单一判据表。
每个新域的设计包必须对照本表写"落点声明"，不合表的过不了规范核对。

## 一、四个落点是什么

| 落点 | 一句话 | 例子 |
| --- | --- | --- |
| **Settings（管理设置）** | 机器/用户/组织级的一次性配置：本体、凭据、置备、策略、运营 | provider 定义与凭据引用、MCP/LSP 连接定义、记忆引擎置备（Docker/端口）、扩展安装与批准、管理员强制策略、遥测/数据保留/更新 |
| **资源库（内容资源管理面）** | 内容与扩展的**本体**管理：安装/卸载/版本/来源 | Skill 包、指令/人格、命令模板、子代理定义、扩展包（hooks/插件/自定义工具）、LSP server 定义 |
| **Profile（预设层）** | 会话起点的**引用+覆盖组合**，不拥有任何本体 | 选哪个 provider/model、effort/预算/超时值、启用哪些 skill/指令/子代理、挂哪些 MCP、记忆开关与预算、压缩/shell/重试策略、权限期望、扩展启用集 |
| **会话区（输入框上下）** | 单会话内的**临时覆盖与即时操作** | 切模型、临时开关某 skill/记忆、工具调用审批、附件准备状态、命令面板、三态发送状态 |

资源库与 Settings 的分工：资源库管"内容物"（可安装、有版本、被引用），
Settings 管"机制与策略"（凭据、服务置备、管理约束）。二者同属管理面，
都不随会话走。

## 二、十条判据（一项配置进哪里，按序问）

1. **作用域**：全机/用户/组织 → Settings；会话起点的预设组合 → Profile；
   仅本会话、可随时退 → 会话区。运行状态（会话记录/压缩产物/记忆正文/进程）
   **三个都不进**。
2. **本体 vs 引用**：本体归资源库或 Settings；Profile/会话区只持引用、开关、
   参数值。绝不把内容物或连接定义复制进 Profile。
3. **凭据红线**：secrets 只存在于 Settings 的凭据引用；Profile、会话区、
   git 仓永不出现明文。
4. **优先级链**：管理员策略 > 会话临时覆盖 > Profile > 域默认值。高者胜；
   被覆盖项在编辑处就地标注来源（"来自会话覆盖/来自 Profile X/被策略锁定"），
   **不新增常驻状态组**（profile-implications 既有口径）。
5. **生效方式**：每项配置必须声明生效语义（请求参数/原生 API/reload/重启/
   下次会话/未知）。会话区只收"即时或下次提交生效"的项；需重启的项留在
   Profile/Settings 并如实标注。
6. **强制策略不可越过**：permissions/sandbox 的管理员约束在 Settings/组织层；
   Profile 只能表达"允许范围内的期望"，被策略禁止时拒绝或诚实说明受限，
   不降级伪装。
7. **注册制**：任何 UI 入口（Settings 分区、Profile 编辑项、会话区控件、
   命令面板命令）都必须由所属域经贡献点注册（C2 facet / addEditor / 会话区
   贡献面 / 命令注册）。没有注册点的域不得硬塞界面。
8. **贡献者卸载**：域卸载后，其 Settings 分区/Profile 编辑项/会话区控件隐藏，
   数据保留；再次应用缺失能力不得假装已应用。
9. **失败诚实**：任何落点的应用失败必须就地说明原因；会话区的失败不得静默
   回退到旧值装作成功。
10. **隐私与第三方**：切 Profile/会话操作不得静默开启遥测；第三方引擎
   （如 mem0）的标注在 Settings、相关界面与 THIRD-PARTY-NOTICES 同现。

## 三、六大类 × 落点速查表

| 大类 | 本体（Settings/资源库） | Profile | 会话区 |
| --- | --- | --- | --- |
| 参数配置 | provider 定义+凭据引用（Settings） | model/effort/预算/超时/请求级 retry | 切模型（不打断输出，下次提交生效） |
| 内容资源 | Skill/指令/人格/命令模板/子代理 本体库 | 启用集与选择、配置值 | 临时开关；命令面板（斜杠命令） |
| 服务绑定 | MCP/LSP 连接与 server 定义、记忆引擎置备（Settings） | 挂载选择、预算、后端引用 | 连接状态/重连入口（诊断可见） |
| 可执行扩展 | 扩展包安装+**强制批准链**（哈希/版本 pin，资源库×Settings 双审） | 启用集 | 调用时的审批确认 |
| 强制策略 | 管理员策略、原生 sandbox 配置（Settings/组织层） | 期望规则（受策略约束） | 工具调用审批、三态发送状态 |
| 运行偏好 | 记忆等策略指向的服务本体（Settings） | 压缩/记忆键/shell/重试 四组值 | 临时调整（即时或下次提交类） |

## 四、本表钉死/重申的两个细节

- **会话区也是注册制**：会话区快捷控件是第四种贡献面，归 chat/各域经贡献点
  注册，规则与 Settings/Profile 的注册制完全同构——这是本次梳理补明确的。
- **批准属于管理面**：扩展的批准（人对"这份代码可以跑"的确认）是 Settings/
  资源库层的**持久事实**，不是会话区的一次性点击；会话区只承接"这次调用
  放不放行"的即时审批。

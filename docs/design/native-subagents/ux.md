# UX：定义库、Profile 选择与 Chat

## Settings 中的定义库

列表按来源“我的/项目/某 Profile 专用/仅原生发现”过滤，显示名称、目标品牌适用性、修订、最后批准来源、是否归档。详情区是短用途描述、角色正文、引用的模型/工具/MCP/Skill/运行限制及目标版本支持事实；可创建、复制、预览差异、发布新修订、归档。默认只读查看原生发现项，明确标“非 Ordessa 管理”。源码预览纯文本/安全 Markdown，不执行语法，不加载远程图片，不显示 secret。

存内容不自动启用，发布新版不移动现有固定版。导入先显示来源、文件摘要、格式/引用诊断与将来权限影响，再显式批准。目标品牌/version 不可用时仍可存，但设置页不能用绿色“已生效”误导。

## Profile 编辑面

本域向 Profile“能力”分类贡献定义选择器：三态继承/启用某固定修订/禁用受管定义；配置摘要与能力缺口就地解释。项目/用户全局默认在本域 Settings/项目入口独立管理，不把所有定义正文塞进 Profile DB。编辑支持在 Profile 中新建专用定义，但取消未保存弹窗不产生新记录；已明确保存的内容不会因随后放弃 Profile 页面草稿而误删。配置面提供者卸载后隐藏编辑器、保留已存引用；需要发送时给应用操作拒绝原因，不在 Profile 页制造“插件故障”空卡。

工具/权限选项的 UI 显示“请求能力”，不是“已授权能力”。超出实际授权时展示不可应用原因与来源，不能给一个能保存但直接绕过政策的“高级 JSON”表单。归档定义或下线 MCP 不自动改写现有绑定；预览标出悬空引用。

## Chat / 调用

若目标固定版本和当前 native/extension-backed 入口已证可调用，Chat 的 `/` 或 `+` 菜单可由本域贡献“子代理”分组，条目显示角色名称、来源及品牌；执行前仍由现有调用所有者最终授权。若当前品牌只支持定义加载、不能受控显式调用，就只给详情/管理入口，不提供假动作。与 `plugins/commands` 中既有 slash 命令、Skills 同名时必须冲突诊断或命名空间，不根据显示顺序选胜者。

切 Profile 或修改分配在输入工具栏只改选择，当前输出不动；下次用户提交应用失败时，输入草稿保留，提示简短可操作原因。无需“当前/待生效/临时修改”三层常驻标签；详细诊断按需打开。子代理运行的进度/消息/暂停等 UI 由 Chat/工作系统已有运行所有者提供，本插件不能伪造运行状态。

## 交互验收

键盘从库列表进入预览/差异、返回焦点稳定；归档/版本更新对话框明确影响范围；900×600 和 200% 缩放不截断保存/拒绝原因；屏幕阅读器能读出“未验证”“extension-backed”“只读原生发现项”区别。切换 Server/Profile/项目后旧异步结果不落到新目标。provider 卸载只摘本域菜单/编辑器，其余 Chat/Settings 正常。
